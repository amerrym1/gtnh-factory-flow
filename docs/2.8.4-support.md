# GTNH 2.8.4 support

This fork keeps 2.8.4 selectable beside 2.9. The app chooses a machine model
from each recipe's own dataset stamp, so a 2.8.4 plan keeps answering to the
2.8.4 machine table after the active dataset changes.

## What is version-scoped

- `MACHINES_V28` in `src/lib/machines/machine-table.ts` is transcribed from
  GT5-Unofficial tag `5.09.51.482`, the GregTech that GTNH 2.8.4 ships.
  Machines it does not cover fall back to the dataset's own baked stats.
- `machineModelVersionForRecipe` reads `recipe.source.datasetVersionId`
  (`2.8.x` -> `"2.8"`, everything else -> `"2.9"`). The solver threads that
  version through overclocks, heat, parallels, power and config controls.
- `HIDDEN_DATASET_VERSION_IDS` is empty, so a 2.8.4 entry in the manifest is
  offered in the Game picker. `pickDefaultDatasetVersion` still prefers
  `latestStableVersion`, then the newest pack first.

## Building a 2.8.4 dataset

The normalizer output for 2.8.4 is about 1 GB, past Node's default heap. The
runner now sets a 6 GB old-space limit (`GTNH_PIPELINE_NODE_MAX_OLD_SPACE_MB`)
and the texture-icon pass streams line by line when the file is too large to
read whole.

The server pack is enough for recipes; rendering GT metaitem icons needs the
client pack. A full run:

```bash
# 2.8.4 packs (the client pack is only for the icon pass)
curl -L -o pack-284-client.zip \
  https://downloads.gtnewhorizons.com/Multi_mc_downloads/GT_New_Horizons_2.8.4_Java_17-25.zip
curl -L -o pack-284-server.zip \
  https://downloads.gtnewhorizons.com/ServerPacks/GT_New_Horizons_2.8.4_Server_Java_17-25.zip

# Server oracle export, normalize, texture icons
GTNH_DATASET_OUT_DIR=$PWD/out/local-2.8.4 \
GTNH_RAW_EXPORT_DIR=$PWD/raw-export/local-2.8.4 \
GTNH_INSTANCE_DIR=$PWD/instance-server \
GTNH_DATASET_VERSION_ID=local-2.8.4 \
GTNH_DATASET_VERSION_LABEL=2.8.4 \
GTNH_DATASET_CHANNEL=stable \
GTNH_SOURCE_KIND=github-release GTNH_SOURCE_REF=2.8.4 \
GTNH_PACK_LOCAL_ZIP=$PWD/pack-284-server.zip \
GTNH_EXPORT_PACK_KIND=server \
GTNH_RENDER_STACK_ICONS=false \
GTNH_EXPORT_MAX_MEMORY=6G \
GTNH_ORACLE_BUILD_CACHE_DIR=$PWD/oracle-cache \
bash tools/dataset-pipeline/scripts/run-gtnh-oracle-export.sh

# Indexes and compression
export NODE_OPTIONS=--max-old-space-size=6144
node tools/dataset-pipeline/scripts/build-resource-index.mjs out/local-2.8.4/recipes.json
node tools/dataset-pipeline/scripts/build-recipe-index.mjs out/local-2.8.4/recipes.json out/local-2.8.4
gzip -9 -c out/local-2.8.4/recipes.json > out/local-2.8.4/recipes.json.gz
```

`GTNH_EXPORT_MAX_MEMORY` must be at least `3G`: CodeChickenCore refuses to
start the pack below that, and the failure surfaces as a confusing
`Loader.mccversion is null`.

### Icons without a client render

The server export writes jar texture PNGs for ordinary items but leaves GT
metaitems (`gregtech:gt.metaitem.*`) without art; those are rendered from live
ItemStacks by the client pass. A client pass on a small machine takes hours.
`reuse-published-icons.mjs` is the bootstrap used for the published 2.8.4
dataset: it matches resource kind and id against a published sibling dataset
and copies its rendered PNGs where they line up.

```bash
node tools/dataset-pipeline/scripts/reuse-published-icons.mjs \
  out/local-2.8.4/recipes.json out/local-2.8.4 \
  <published>/resource-index.json.gz https://gtnhplanner.com
```

Then rebuild the indexes and gzip again, because the script updates the
dataset's `iconPath`s. The icon-borrow report records how many were copied.
This is a fallback, not a substitute: a client icon export is still the right
answer for a pack whose item ids do not match the published one.

## Publishing locally

Stage the files the app serves under `public/datasets/gtnh/<id>/` and rebuild
the manifest:

```bash
node tools/dataset-pipeline/scripts/rebuild-manifest.mjs
```

`public/datasets/gtnh/` is gitignored; datasets are never committed.

## Known gaps

- `gregtech-ore-veins` and `gregtech-small-ores` are skipped on 2.8.4: the
  exporter is compiled against 2.9's `IStoneType`/`IOreMaterial` API, which
  5.09.51.482 does not have. Recipes, ores in the ore dictionary, underground
  fluids and everything else export normally.
- 77 machine families are transcribed in `MACHINES_V28`; the rest use the
  dataset's scraped stats, which the 2.8.4 export carries.
- The High Current Industrial Arc Furnace is not modelled: its parallels depend
  on the width of the structure the player builds. Fusion reactors and the
  large boilers are power machines handled elsewhere.
